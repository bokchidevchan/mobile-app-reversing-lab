# 03. 동적 분석과 Frida

정적 분석은 앱을 안 켜고 코드를 읽는다. 동적 분석은 앱을 실제로 돌리면서 런타임을 들여다보고 조작한다.

## 언제 동적이 필요한가

정적으로 다 풀리면 동적은 필요 없다. UnCrackable L1처럼 키가 코드에 박혀 있으면 정적으로 끝난다.
동적이 필요해지는 건 값이 코드에 안 보일 때다.

- 문자열을 런타임에 만들어 쓰는 경우(정적으론 조각만 보이고 완성된 값이 안 보임)
- 서버에서 받아온 값, 사용자 입력과 섞이는 값
- 루트/디버그/무결성 탐지를 런타임에 통과시켜야 앱이 계속 도는 경우
- 네이티브(.so)라 정적 역컴파일이 막힐 때, 메모리에서 결과만 가로채는 경우

핵심 아이디어는 하나다. **아무리 잘 숨겨도 앱이 실제로 쓰려면 언젠가 메모리에 평문으로 뜬다.** 그 순간을 가로챈다.

## Frida가 하는 일

실행 중인 프로세스에 JavaScript 엔진을 주입해서, 원하는 함수를 가로채는(hook) 도구다.

- 함수 호출을 가로채 인자를 읽거나 바꾼다.
- 반환값을 바꿔치기한다(예: 루트 탐지 함수가 무조건 false를 뱉게).
- 함수를 직접 호출한다.

Android/iOS 둘 다 되고, 네이티브 함수(strcmp 같은 libc 함수 포함)도 후킹된다.

## Android에서 Frida 붙이는 흐름

앱을 실행할 런타임이 필요하니 에뮬레이터(AVD)를 쓴다. 호스트와 격리돼서 안전하다.

1. `adb root`가 되는 이미지를 쓴다. `google_apis`(플레이스토어 없는) 시스템 이미지가 루팅이 된다.
   `google_apis_playstore`는 안 된다.
2. 아키텍처에 맞는 frida-server를 기기에 올려서 root로 실행한다(에뮬 arm64 → android-arm64 서버).
3. 호스트의 frida가 그 서버에 붙는다.

```
adb -s <기기> root
adb -s <기기> push frida-server /data/local/tmp/
adb -s <기기> shell "/data/local/tmp/frida-server &"
frida -D <기기> -f <패키지> -l hook.js
```

호스트 frida 버전과 frida-server 버전은 맞춰야 한다. 안 맞으면 안 붙는다.
그리고 기기가 여러 개(실기기, 에뮬 여러 대) 붙어 있으면 `-D <기기id>`로 대상을 꼭 지정한다.
실기기를 실수로 건드리면 안 되니까.

## 버전 함정 하나

Frida 17부터 `Java`/`ObjC` 브리지가 런타임에서 분리됐다. frida CLI는 자동으로 얹어주지만,
Python API(`create_script`)로 직접 붙이면 `Java is not defined` 에러가 난다.
Python으로 스크립트를 돌릴 거면 브리지가 내장된 16.x를 쓰거나, 17에선 브리지를 따로 로드해야 한다.

## objection

Frida 위에 얹은 도구. 흔한 후킹을 명령어로 미리 만들어놨다.
`android root disable`, `android sslpinning disable` 한 줄이면 스크립트 없이 우회가 된다.
세밀하게 짜야 할 땐 Frida 스크립트, 흔한 작업은 objection.

## iOS는 어디가 다른가

Frida를 쓰는 건 같지만 실행 환경이 다르다. 자세한 건 04번 문서에 정리했다.
요약하면, App Store 앱은 FairPlay로 암호화돼 있어 정적 분석 전에 복호화 덤프가 필요하고,
동적 분석은 탈옥 기기나 시뮬레이터(소스로 빌드한 앱)에서 한다.
